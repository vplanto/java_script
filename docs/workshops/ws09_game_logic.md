# Воркшоп 9: Логіка гри та Штучний Інтелект (Створення Розумного Бота)

Ми вже вирішили проблему з амнезією нашої гри, захистили паролі та валідували вхідні дані. Але грати проти комп'ютера, який робить ходи абсолютно випадково або передбачувано — це нудно.
У цьому воркшопі ми пройдемо шлях від хаотичного спагеті-коду до елегантного проектування "мозку" для нашого робота, здатного до адаптивного навчання на основі поведінки гравця.

---

## Акт 1: Пастка заплутаного коду (Архітектура правил)

Уявіть ситуацію: ви пишете базову перевірку переможця. Новачок одразу починає писати каскад розгалужень `if/else`:

```javascript
// Код початківця: пастка масштабованості
function getWinner(p1, p2) {
    if (p1 === p2) return 'draw';
    if (p1 === 'Rock' && p2 === 'Scissors') return 'player';
    if (p1 === 'Paper' && p2 === 'Rock') return 'player';
    if (p1 === 'Scissors' && p2 === 'Paper') return 'player';
    // ... десятки інших комбінацій
    return 'computer';
}
```

А тепер приходить замовник і каже: *"Ми розширюємо гру! Додаємо легендарні версії 'Камінь-Ножиці-Папір-Ящірка-Спок' (як у теорії великого вибуху)"*.
Спроба розширити купу `if/else` призведе до виникнення десятків нових ліній коду та неминучих багів.

### Інженерне рішення: Декларативна структура даних
Замість розгалуження коду ми переносимо логіку в **структуру даних**. Ми описуємо правила як граф (список суміжності), де кожен ключ — це вибір гравця, а значення — масив елементів, які він перемагає.

```javascript
const RULES = {
    'Rock': ['Scissors', 'Lizard'],     // Камінь перемагає Ножиці та Ящірку
    'Paper': ['Rock', 'Spock'],         // Папір перемагає Камінь та Спока
    'Scissors': ['Paper', 'Lizard'],     // Ножиці перемагають Папір та Ящірку
    'Lizard': ['Spock', 'Paper'],       // Ящірка перемагає Спока та Папір
    'Spock': ['Scissors', 'Rock']       // Спок перемагає Ножиці та Камінь
};

function getWinner(p1, p2) {
    if (p1 === p2) return 'draw';
    return RULES[p1].includes(p2) ? 'player' : 'computer';
}
```
> [!TIP]
> **Перевага дизайну:** Тепер для розширення правил гри вам не потрібно змінювати жодного рядка логіки у функції `getWinner`. Ви просто редагуєте словник `RULES`. Це класичне втілення принципу масштабованості.

## Акт 2: Багатоголовий робот (Патерн Strategy)

Наступне завдання: додати рівні складності для бота. Нам потрібні:
1. **Дурний бот** (Deterministic) — для юніт-тестів та налагодження.
2. **Випадковий бот** (Stochastic) — класичний суперник.
3. **Розумний бот** (Adaptive) — що адаптується до гравця.

Початківець написав би гігантський `switch(difficulty)` всередині обробника кліку гри. Це створює сильне зачеплення (tight coupling) коду.

### Інженерне рішення: Патерн Strategy
Ми створюємо окремі, ізольовані функції для кожної поведінки ШІ, які мають однаковий інтерфейс (приймають однакові аргументи та повертають хід). В основному циклі ми просто підміняємо посилання на поточну стратегію.

```javascript
// 1. Дурна стратегія: завжди камінь
function deterministicStrategy() {
    return 'Rock';
}

// 2. Рандомна стратегія: рівноймовірний вибір
function randomStrategy() {
    const moves = Object.keys(RULES);
    const randomIndex = Math.floor(Math.random() * moves.length);
    return moves[randomIndex];
}

// Посилання на поточну стратегію, яка може змінюватися динамічно
let currentAiStrategy = randomStrategy; 

// Виклик у циклі гри залишається незмінним і чистим:
const computerMove = currentAiStrategy();
```

## Акт 3: Робот, що читає думки (Адаптивний ШІ через Марковські ланцюги)

Люди дуже погано вміють генерувати випадкові послідовності. Дослідження показують: якщо гравець вибрав `Rock` і програв, у наступному раунді він з високою ймовірністю вибере інший знак (наприклад, `Paper`).
Ми використаємо це і побудуємо адаптивного бота на основі **ланцюгів Маркова**.

Робот буде зберігати історію переходів гравця у спеціальній матриці:

```javascript
// Матриця переходів: який хід робить гравець після свого попереднього ходу
const transitionMatrix = {
    'Rock': { 'Rock': 0, 'Paper': 0, 'Scissors': 0 },
    'Paper': { 'Rock': 0, 'Paper': 0, 'Scissors': 0 },
    'Scissors': { 'Rock': 0, 'Paper': 0, 'Scissors': 0 }
};
```

### Як це працює:
1. Мы записуємо кожну зміну ходу гравця: наприклад, якщо в раунді 1 гравець вибрав `Rock`, а в раунді 2 — `Paper`, ми робимо `transitionMatrix['Rock']['Paper']++`.
2. Перед своїм ходом бот дивиться на *останній* хід гравця (наприклад, `Rock`).
3. Бот аналізує матрицю для `Rock` та знаходить варіант з найбільшим лічильником (наприклад, `Paper`, тобто гравець найчастіше після каменю обирає папір).
4. Бот прораховує контр-хід: щоб перемогти очікуваний `Paper`, бот має вибрати `Scissors`.

```javascript
let lastPlayerMove = null;

function updateTransitionMatrix(newPlayerMove) {
    if (lastPlayerMove && transitionMatrix[lastPlayerMove]) {
        transitionMatrix[lastPlayerMove][newPlayerMove]++;
    }
    lastPlayerMove = newPlayerMove;
}

function adaptiveStrategy() {
    if (!lastPlayerMove) return randomStrategy(); // Перший хід робимо випадково
    
    const predictions = transitionMatrix[lastPlayerMove];
    
    // Знаходимо хід гравця з найбільшою ймовірністю
    let predictedMove = 'Rock';
    let maxCount = -1;
    for (const move in predictions) {
        if (predictions[move] > maxCount) {
            maxCount = predictions[move];
            predictedMove = move;
        }
    }
    
    // Шукаємо контр-хід, який переможе прогнозований хід гравця
    return Object.keys(RULES).find(move => RULES[move].includes(predictedMove));
}
```

> [!WARNING]
> **Проблема малої вибірки:** Якщо бот почне приймати рішення адаптивно вже на 2-му раунді, його рішення будуть хибними (через брак статистики). Для стабільної роботи бот має назбирати мінімум **5 раундів історії**, працюючи в режимі випадкового вибору, і лише потім активувати адаптивний мозок.

## Акт 4: Рівновага Неша та теорія ігор (Nash Equilibrium & GTO)

Якщо наш Адаптивний бот такий розумний, чи може він програти?
Так, якщо його опонент діє ідеально хаотично. 

У теорії ігор існує поняття **Рівноваги Неша** (Nash Equilibrium) — стратегії, при якій жоден із гравців не може збільшити свій виграш, в односторонньому порядку змінивши свій вибір. 

* Для класичної гри "Камінь-Ножиці-Папір" рівновагою Неша є **чистий рандом** (кожен варіант вибирається з ймовірністю рівно 33.3%). Ця стратегія називається **GTO (Game Theory Optimal)**.

> [!IMPORTANT]
> **Парадокс теорії ігор:** 
> * **Random Bot (GTO):** Його неможливо обіграти математично на великій дистанції. Він завжди зведе гру в нуль (нічию) проти будь-якого суперника (навіть суперорганічного ШІ).
> * **Adaptive Bot:** Намагається знайти вразливість у паттернах людини, щоб отримати позитивний вінрейт. Проте, якщо людина помітить це і змінить свої паттерни або гратиме абсолютно випадково, адаптивний бот почне помилятися через застарілі дані у своїй матриці.

## Контрольні питання

1. Чому структура даних `RULES` краще для опису правил гри, ніж розгалужений блок `if/else`?

<details markdown="1">
<summary>Відповідь</summary>

Структура даних розділяє самі правила гри (дані) та алгоритм визначення переможця (код). Це дозволяє додавати чи змінювати правила (наприклад, розширити гру до 5 елементів) шляхом редагування одного об'єкта, не переписуючи логіку перевірок. Це зменшує ризик багів та підвищує масштабованість.

</details>

2. Що таке патерн Strategy і як він допомагає уникнути жорсткого зчеплення (tight coupling) коду?

<details markdown="1">
<summary>Відповідь</summary>

Патерн Strategy дозволяє виділити різні алгоритми (поведінки ШІ) в окремі взаємозамінні функції з однаковим інтерфейсом. Завдяки цьому головний ігровий цикл не залежить від деталей реалізації складності бота — він просто викликає поточну стратегію через змінну-посилання, що полегшує підтримку та розширення коду.

</details>

3. Як працює ланцюг Маркова для прогнозування ходів гравця і чому йому потрібна попередня вибірка в 5 раундів?

<details markdown="1">
<summary>Відповідь</summary>

Ланцюг Маркова прогнозує наступний крок на основі поточного стану, використовуючи матрицю ймовірностей переходів. Попередня вибірка у 5 раундів потрібна, щоб уникнути помилок через надто малий обсяг даних: якщо гравець зробив один крок, бот може подумати, що це 100% закономірність, хоча це випадковість. Статистика стає репрезентативною лише після кількох раундів.

</details>

4. Що таке Рівновага Неша в грі "Камінь-Ножиці-Папір" і чому випадковий бот ніколи не буде в мінусі проти найрозумнішого гравця на великій дистанції?

<details markdown="1">
<summary>Відповідь</summary>

Рівновага Неша тут — вибір кожного варіанту з однаковою ймовірністю 33.3% (ідеальний рандом). Якщо бот грає строго випадково, його ходи не мають жодних закономірностей чи паттернів. Оскільки суперник не може підлаштуватися під повну випадковість, очікуване значення виграшу (EV) для обох гравців на великій дистанції математично дорівнюватиме нулю, роблячи гру безпрограшною для бота.

</details>
